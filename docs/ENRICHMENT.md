# Автоматическое обогащение каталога

Каждый новый или изменившийся фильм сам проходит путь: задание → метаданные →
проверка типа записи → канонические жанры/темы/тон → семантика (если включена) →
проверка противоречий → версионированный профиль → доступность в подборе.
Владелец не размечает фильмы руками; ручной разбор нужен только для исключений.

## Два расхождения с исходной постановкой

**1. Провайдер — не TMDb.** Задача была написана под TMDb (`append_to_response`,
маппинг keyword ID). У проекта TMDb-ключа нет и не будет: письмо верификации не
приходит, см. `CLAUDE.md`. Источники — kinopoisk.dev и OMDb, уже используемые
продуктом. Модель `NormalizedMovieSource` провайдеро-нейтральна, поэтому
подключение TMDb позже — это новый адаптер, а не переделка правил.

Практическое следствие: у наших провайдеров **нет keywords**. Слой «проверенное
соответствие provider keyword → канонический тег» реализован на проверенных
текстовых оборотах в описании (`mappings.REVIEWED_TONE_MARKERS`) плюс возрастной
рейтинг (`ratingMpaa`/`ageRating`/OMDb `Rated`) — последний оказался единственным
надёжным источником про аудиторию.

**2. Семантический классификатор выключен — по замеру, а не из осторожности.**

| вариант | RSS | 288 фильмов | принято меток |
|---|---|---|---|
| `disabled` (по умолчанию) | 0 | — | — |
| `lexical` (без зависимостей) | 0 | 0.2 c | **0 из 288** |
| `sentence_transformers` (paraphrase-multilingual-MiniLM-L12-v2) | **1115 МБ** | 1.0 c (4 мс/шт) | ~40 |

Машина Fly — **256 МБ**. Трансформерная модель туда не помещается: нужен платный
воркер ≥1 ГБ. Качество тоже неоднозначное: модель верно находит «Доктор
Стрейнджлав» → `satirical` (0.327), но при этом ставит `dark_comedy` (0.254)
фильму «К-9: Собачья работа» — ровно тот дефект, который чинился, — и `inspiring`
(0.409) «Рапунцель». Лексический вариант на пониженном пороге называл
«Человека-паука» сатирой.

Поэтому в проде работает детерминированный слой, обе реализации остаются
подключаемыми:

```
MOVIE_SEMANTIC_CLASSIFIER=disabled|lexical|sentence_transformers
MOVIE_SEMANTIC_MODEL_NAME=<модель>
```

Включение sentence-transformers требует решения о платном воркере — это решение
владельца, а не конвейера.

## Устройство

```
enrichment/
    taxonomy.py       канонические жанры, темы, тоны, флаги аудитории, версии
    models.py         NormalizedMovieSource, доказательства, профиль, source hash
    provider.py       kinopoisk/OMDb → нормализованный источник
    mappings.py       проверенные соответствия провайдер → канон
    extraction.py     детерминированное извлечение (работает всегда)
    semantic.py       подключаемый классификатор (disabled по умолчанию)
    merge.py          старшинство доказательств, противоречия, уверенность
    validation.py     проверки здравого смысла над готовым профилем
    repository.py     версионированные профили и ручные правки
    queue.py          долговечная очередь (FOR UPDATE SKIP LOCKED)
    service.py        обработка одного задания
    reconciliation.py добор пропущенного и устаревшего
    worker.py         отдельный процесс (Fly process group `worker`)
```

## Один словарь на весь продукт

Идентификатор `dark_comedy` — один и тот же в анкете, в признаках фильма, в
составном требовании гейтинга и в коде причины:

```
ответ анкеты h1=dark
    → составное требование mood.COMPOUND_REQUIREMENTS[("h1","dark")]
    → маркер тона dark_comedy (mood.PLOT_MARKERS / mappings.REVIEWED_TONE_MARKERS)
    → тон профиля tones=["dark_comedy"]
    → код причины DARK_COMEDY_TONE (reasons.py)
    → текст «Чёрный юмор и мрачный тон» (reasons.TEXTS + фронтенд)
```

## Эксплуатация

```bash
# согласование: найти пропущенные и устаревшие профили
python scripts/reconcile_movie_enrichment.py --dry-run

# бэкфил каталога
python scripts/backfill_movie_enrichment.py --only-missing --batch-size 50

# ручной обзор по названиям (главная проверка качества)
python scripts/evaluate_movie_features.py --sample 50
python scripts/evaluate_movie_features.py --tone dark_comedy
python scripts/evaluate_movie_features.py --low-confidence
```

Диагностика в проде — `GET /api/admin/enrichment` и
`GET /api/admin/enrichment/exceptions` (только editor/admin, роль резолвится на
сервере).

## Откат

Ни одна операция отката не требует отката миграции:

0. предыдущий рабочий релиз: `fly releases --app addict-film`, откат —
   `fly deploy --image <образ предыдущего релиза>`;
1. `fly scale count worker=0` — воркер останавливается, веб не затронут;
2. `MOVIE_SEMANTIC_CLASSIFIER=disabled` — семантика выключается;
3. готовые профили остаются активными, каталог доступен;
4. `MOOD_LAYER_ADMIN_PREVIEW=0` / `MOOD_LAYER_ENABLED=0` — слой настроения
   выключается целиком, подбор возвращается к прежней логике.

Профиль никогда не стирается до успешного пересчёта: при смене версии он
помечается `stale`, продолжает работать и заменяется атомарно.

## Инварианты, введённые в проходе укрепления

Нарушение любого из них — регрессия, а не «другой стиль». Каждый закрыт тестом.

1. **Бюджет Kinopoisk списывает только `kinopoisk._request`.** Ни один вызывающий
   код не тратит квоту заранее: один сетевой запрос = одна единица, попадание в
   кэш = ноль. Проверяется тестом, который сканирует исходники.
2. **Настроение входит в рейтинг ровно один раз.** `apply_mood_layer` кладёт в
   `_score` смешанное значение, поэтому рольевые формулы обязаны брать
   `normalized_base_score()` — исходный базовый счёт.
3. **Сериал, эпизод и короткий метр не возвращаются в подбор фильмов никаким
   откатом.** Пустая выдача честнее подмены; `unknown` остаётся годным как
   legacy-совместимость.
4. **Хеш источника считается из КАТАЛОЖНЫХ данных плюс ручной правки.**
   Метаданные, дотянутые у провайдера на лету, в него не входят — иначе
   согласование никогда не совпадёт с сохранённым значением и будет вечно
   переставлять фильм в очередь.
5. **Постановка задания и запись профиля атомарны.** `INSERT ... ON CONFLICT`, а
   не «сначала посмотрим, потом вставим»: между проверкой и вставкой помещается
   второй процесс.
6. **Согласование идемпотентно.** Второй проход подряд ставит ноль заданий.
7. **Политика устаревшего профиля явная.** `stale` временно годен, но с урезанной
   уверенностью (×0.85, потолок 0.65); `invalid`, `failed`, `pending` и
   `low_confidence` в строгий режим не попадают.
8. **Инициализация схемы в Postgres сериализована** консультативной блокировкой:
   веб и воркер стартуют одновременно и оба зовут `init_db`.
9. **Сопоставление маркеров — от границы слова**, одна реализация на весь проект
   (`backend/text_matching.py`). Маркеры хранятся как префиксы слов, поэтому
   защита от ложных срабатываний живёт в СОСТАВЕ маркеров: у чёрной комедии это
   полные обороты, а не корень «черн».

## Изображение для полноэкранного подбора (hero)

Экраны «Случайный из Хочу» и «Умный случайный фильм» показывают один фильм во
весь экран. Режим изображения выбирает **сервер**, а не фронтенд.

Почему не `backdrop_url`: НАЛИЧИЕ этого поля ничего не доказывает. У kinopoisk
там встречаются и вертикальные обложки, и 640×360, и кадры с выжженным
логотипом. Растянутый на всю ширину постер выглядит как поломка вёрстки — ровно
этот дефект и чинится. Поле сохранено для карточек подборок, но в hero
автоматически не повышается.

Источник — **Fanart.tv v3.2** (`/movies/{imdb_id}`). Он отдаёт ширину, высоту,
язык и число лайков ДО скачивания файла, поэтому отбор идёт по метаданным.
Ключи: project key заголовком `api-key`, личный — `client-key`; оба
одновременно поддерживаются официально.

### Что имеет право называться кадром

```
ширина >= 1600 и высота >= 850
соотношение 1.55 … 2.20
счёт >= 0.72
```

Счёт (`hero_media.score_fanart_background`):

```
разрешение 0.45 + соотношение 0.30 + лайки 0.15 + язык 0.10
```

Разрешение и композиция весят больше популярности: лайки говорят о вкусе
загрузившего, а не о пригодности файла под широкий блок. Кадр без текста
(`lang=00`) получает максимум по языку — интерфейс двуязычный, и вшитый в
картинку английский заголовок в русском интерфейсе выглядит чужеродно.

Не прошло — `poster_blur`: вертикальный постер по центру на своей же размытой
копии. Резкая и размытая отрисовка используют ОДИН URL, поэтому вторая берётся
из кэша браузера.

### Эксплуатация

```bash
# посмотреть выбор, ничего не записывая
python -m enrichment.hero_backfill --limit 10 --dry-run

# консервативный бекфил
python -m enrichment.hero_backfill --limit 25 --batch-size 5 --concurrency 2

# точечная перепроверка одного фильма
python -m enrichment.hero_backfill --film-id <ID> --force
```

Сводка — в `GET /api/admin/enrichment` (поле `hero_media`).

### Инварианты

10. **Fanart не вызывается на пути пользовательского запроса.** Рулетка и умный
    случайный читают только каталог; внешние вызовы живут в воркере.
11. **Второй проход подряд не делает ни одного внешнего запроса.** Идемпотентность
    держится на отборе кандидатов: фильм со свежим `hero_checked_at` в выборку не
    попадает. Отдельный тип задания в очереди не заводился — там CHECK на
    `job_type`, и расширять его пришлось бы блокирующей миграцией ради работы,
    у которой уже есть естественный ключ дедупликации.
12. **`hero_checked_at` отмечает и ПУСТУЮ попытку.** Фильм без imdb_id и без
    постера иначе стучался бы наружу на каждом круге воркера.
13. **Временный сбой источника не стирает сохранённый выбор** и не ставит отметку
    проверки: иначе таймаут уводил бы фильм из очереди на 30 дней.
14. **Скачивается ровно один выбранный файл** — чтобы поймать «метаданные врут»:
    content-type, размер и (для PNG/JPEG) реальные размеры из заголовка. Pillow
    ради этого в образ не тянем.
15. **Сроки перепроверки:** сильный кадр (>=0.85) — 90 дней, слабее — 30 дней,
    запасной постер у свежего фильма — 7 дней, у старого — 30 дней.

### Откат

```bash
fly secrets set FULLSCREEN_SINGLE_PICK_ENABLED=0 -a addict-film   # только интерфейс
fly secrets set FANART_HERO_ENABLED=0 -a addict-film              # внешние запросы
```

Колонки и накопленные значения при откате НЕ удаляются: с выключенными флагами
они безвредны, а повторное включение не потребует нового обхода каталога.
