# Movie Mini App (Addict Film) — інструкції для агента

**Публічний Telegram Mini App** для пошуку, збереження й оцінювання фільмів
(модель Кінопоїск/Letterboxd). Будь-який Telegram-юзер реєструється при першому
вході; у кожного свій список і оцінки, каталог фільмів спільний,
community-рейтинг = середня оцінка всіх юзерів. Є опціональний шар «Пара»
(двоє юзерів бачать спільну статистику й сумісність).

Бот **Addict Film**, живе на **https://addict-film.fly.dev**.

чіпати**, він живе окремо (launchd `com.moviebot`).

## Жорсткі правила
- **Весь UI — російською.** Коментарі в коді — російською/українською.
- **TMDb не пропонувати** — у власника не приходить лист верифікації, ключ
  недоступний. Основне джерело — **kinopoisk.dev** (токен через @kinopoiskdev_bot).
- **kinopoisk free = 200 запитів/добу на ключ; у нас 4 ключі = ~800/добу.**
  Платний тариф/моніторинг CU НЕ пропонувати, поки власник сам не скаже — кеш
  робить це майже нерелевантним (див. нижче).
- **Мультитенантність:** дані ізолюються по `user_id`. Схема: `users` /
  `films` (спільний каталог, dedup по imdb_id) / `user_films` (per-user
  статус/оцінка/коментар). Реєстрація будь-кого з валідним initData, без whitelist.
- **Секрети лише у Fly secrets** (`fly secrets`), НЕ в коді. Локальний `.env` у
  ворктрі — плейсхолдери (`apikey=x`), тому локальні тести проти зовнішніх API
  не працюють; ганяти через `fly ssh console` (там бойові секрети) або живий прод.
- **Стиль спілкування:** максимально стисло, факти без «води».

## Стек і інфраструктура (АКТУАЛЬНО — курс змінювався, старі згадки SQLite застарілі)
- **Backend:** FastAPI, з `backend/`. Async усюди (aiohttp).
- **БД:** **Postgres (Neon, Frankfurt)** у проді; локально SQLite. Абстракція —
  `backend/db_runtime.py` (aiosqlite-сумісний адаптер над asyncpg; тримає РЕАЛЬНУ
  транзакцію на весь `connect()`-блок — без явного `commit()` зміни губляться,
  як у SQLite). `DATABASE_URL` — секрет Fly. Telegram id > int32 → колонки BIGINT.
  SERIAL/AUTOINCREMENT — dual через `_PG`. Міграції — `_add_column_if_missing`
  (ізольована транзакція на кожну колонку).
- **Хостинг:** **Fly.io, 2 машини (fra)**, health-check `/healthz`, keep-warm
  (`auto_stop_machines=false`). CI: push у `main` → авто-деплой (`.github/
  workflows/fly-deploy.yml`, `FLY_API_TOKEN` — скоуплений deploy-токен).
- **Моніторинг:** Sentry (`SENTRY_DSN` секрет, тільки помилки). Fly має вбудовані
  метрики. Prometheus/Grafana/Locust — НЕ треба, оверкіл для масштабу.
- **Авторизація:** Telegram initData HMAC (`backend/auth.py`), заголовок
  `X-Init-Data`. Для локального тесту UI — підписати initData бойовим `BOT_TOKEN`
  на сервері (`fly ssh console`) + пропатчити `window.api` у браузері.
- **Frontend:** ванільний JS + Telegram WebApp SDK. Фіксована **тёмна тема**
  (не залежить від теми Telegram). Постери через проксі `/img` (обхід CDN-блоку).
  Кеш-бастинг: `?v=N` у `index.html` — **бампати щоразу при фронт-деплої**
  (інакше Telegram-webview віддає старе). Зараз `v=24`.
- venv: `/Users/denyszapriahailo/movie_miniapp/.venv/` (у головному дереві, не
  у ворктрі). Запуск: `.venv/bin/uvicorn main:app --port 8077` з `backend/`.

## Ключові механізми
- **Резолвер постерів** (`backend/posters.py`): kinopoisk-по-imdb → kinopoisk-за-
  назвою (guarded: точний збіг назви+рік ±1) → OMDb з апскейлом. Kinopoisk —
  пріоритет (якісніші постери). Бекфіл: `scripts/backfill_posters.py`.
- **Проксі `/img`** (`backend/main.py`): allowlist хостів (анти-SSRF), диск-кеш
  на томі `/data/imgcache`, 2 ретраї до CDN, звірка Content-Length. Фронт:
  тайли просять 300x450 (не 600x900), бекдропи 672x378 (не 1344x756), `__imgRetry`
  — ретрай оборваної картинки у відв'язаному Image() (не блимає живим тегом).
- **Кеш пошуку** (`backend/search.py`): L1 in-memory (6 год) + L2 у Postgres
  (14 днів, спільний). Кеш-хіти не витрачають ліміт kinopoisk. Денний бюджет
  зовнішніх викликів — у Postgres (`search_budget`, атомарний UPSERT, крос-
  інстансний), `DAILY_SEARCH_BUDGET=800`. Per-user throttle in-memory.
- **Дані фільму:** kinopoisk.dev дає poster, backdrop, ageRating, persons(з photo).
  Колонки: `films.poster_url/backdrop_url/age_rating/actors_photos(JSON)`.
  `/api/movies?status=watched` віддає повний список з watched_at/runtime/year —
  багато статистики рахується КЛІЄНТОМ звідси, без нового бекенда.

## Що вже зроблено (усе живе на проді, перевірено)
- Мультитенантний фундамент, community-рейтинг, кеш+rate-limit, discovery
  (`/api/browse`: популярне/топ/жанри), персональна статистика.
- **Пара**: інвайт через deep-link (`startapp=inv_`) або код, сумісність,
  спільна статистика. Атомарний `accept_invite` (race-safe).
- **Міграція на Postgres/Neon** + масштабування (2 машини, крос-інстансний бюджет).
- **Мульти-джерельний резолвер постерів** + бекфіл + upgrade OMDb→kinopoisk.
- **backdrop + age_rating + фото акторів** (реальні, з kinopoisk).
- **Підбірки (Collections)**: адмін/редактор кидає фільми в іменовані добірки
  зі звичайного пошуку. Роль: `ADMIN_USER_IDS` (bootstrap-секрет) або `users.role`.
  Секція «🎬 Подборки» на Головній. Ендпоінти `/api/collections*`,
  `/api/admin/collections*` (гейт `require_editor`).
- **Преміум-редизайн (Quiet Luxury):** Головна, деталі фільму, підбірки,
  **статистика** (фаза 1+2: кільце пари, донат жанрів, heatmap активності,
  перегляди по місяцях, порівняння з партнером, досягнення, інфо-картки).
- Zoom вимкнено (viewport + touch-action), фікси зникання постерів.
- Deploy: `fly deploy -a addict-film --now`. Прод-БД — на постійному томі Neon.

## Що ще треба зробити (беклог, за пріоритетом)
1. **ЯСНІСТЬ статистики** (просив власник — головне зараз): екран став багатий,
   але «незрозуміло що куди й для чого». Треба: підписи/легенди до графіків,
   пояснення метрик (що таке «сумісність», «серія», heatmap), можливо згорнути
   частину блоків або додати короткі описи. НЕ додавати нових даних — зробити
   наявне зрозумілим.
2. **Багатша статистика пари** (просив власник): зараз пара = кільце + факти.
   Розширити (спільний heatmap, хто що додав, тренд сумісності) — але тільки
   коли ясність із п.1 наведено.
3. Веб-логін поза Telegram (Telegram Login Widget) — для сайту в браузері.
4. Опціональний бот-сповіщення (нагадати оцінити) — є заготовка
   `db.get_unrated_watched`, самого бота нема.
5. Крос-юзер рейтинг («топ N% пар») — свідомо пропущено, бо при малій базі це
   фейк. Додати коли база виросте.
